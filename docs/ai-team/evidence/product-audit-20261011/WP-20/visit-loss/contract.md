# Durable visit loss provenance
LiveMetricVisitLoss stores (vendorId, liveId, versionId, visitedAt), never visitorId/browserHash/person identity. A point represents missing facts in [visitedAt,visitedAt+1ms). Duplicate losses at the same timestamp coalesce. This does not recreate erased facts or prove collection coverage.
The statement DELETE trigger inserts losses and invalidates reports in the same transaction, under existing version locks. Rollback removes both operations. Deleting a visitor retains the version-level gaps. Loss UPDATE/DELETE while the version exists and TRUNCATE are refused; version removal cascades the loss metadata. RLS/default deny and composite tenant FK apply. No formal production retention schedule or production operation is introduced.
Historical deletion before this migration cannot be reconstructed. Collection-coverage start must never predate verified collector and loss tracking activation; otherwise history remains unknown. Empty loss table alone is not an audited complete history.
