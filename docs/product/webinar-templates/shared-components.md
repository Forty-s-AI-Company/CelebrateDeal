# 20 個 Webinar 範本的共用元件與分批計畫

> 依據：`research.md` 的 20 個原型、`specs/01～20`。
> 本文件說明三件事：已有哪些元件可以重用、要新增哪些元件與基礎設施、如何分 4 批（每批 5 個範本平行）實作。

## 2. 基礎設施缺口（必須先做，否則「不跑版」無法驗收）

### I-1 平板斷點（最高優先）

- **現況**：公開頁在 `public-funnel-document.tsx` 用 `matchMedia("(max-width: 639px)")` 把 viewport 切成 `mobile`／`desktop` 兩種，第一次 render 一律是 desktop。
  - 768 與 1024 寬會套用桌機版面。`columns_3`／`columns_4` 在 768 寬只剩約 160–210px 一欄，繁中標題很容易擠壞。
  - 手機第一次 render 先出現桌機版面，接著才切換，會產生版面跳動（CLS）。
- **要求**：
  1. 新增平板斷點（建議 640–1079px，讓 1024 寬落在平板，否則 4 欄在 1024 寬每欄只剩約 220px，違反 `qa-standards.md` L-10）。`columns_3`／`columns_4` 在平板改成 2 欄，`columns_2` 預設維持 2 欄但縮小 gap。展示元件的 `columns` 也要跟著降欄。
  4. 節點 `overrides` 新增 `tablet`（與既有的 `mobile` 同形），讓範本可以指定平板版的樣式或改成單欄（例如 02 在 768 寬把首屏改成上下堆疊）。
  2. 優先用 CSS（container query 或 media query）處理欄數，讓 SSR 第一個畫面就正確。若仍保留 JS viewport，首次 render 前不得出現錯誤欄數造成可見跳動。
  3. 編輯器預覽加「平板」切換，或在 browser-qa harness 加 responsive 模式（見 `qa-standards.md` §5）。
- **負責**：批次 1 的元件 PR（engineer）。這是共用 renderer 的改動，同一時間只能有一個 writer。

### I-2 字型實際載入與新字型選項

- **現況**：`FUNNEL_FONT_OPTIONS` 只列字型名稱（Noto Sans TC、Noto Serif TC 等）。沒有安裝這些字型的訪客，實際看到的是系統字型（微軟正黑、蘋方），範本的設計效果無法保證。
- **四種做法比較**：

  | 做法 | 說明 | 優點 | 缺點 |
  |---|---|---|---|
  | **A. `next/font/google` 自架（建議）** | 建置時下載 Google Fonts 的 CSS 與字檔，跟網站其他靜態檔一起由自家網域提供（`node_modules/next/dist/docs/01-app/03-api-reference/02-components/font.md`：瀏覽器不會對 Google 發出請求） | 不必放寬 CSP、不洩漏訪客 IP 給第三方；字型度量自動調整，CLS 低；保留 Google 的 unicode-range 分片，只下載頁面用到的字 | 只能使用建置時登記的字族，商家不能自由加字型；繁中字族要設 `preload: false`（CJK 字檔很大），並實測分片是否保留 |
  | B. Google Fonts CDN（`<link>`） | 公開頁依頁面設定動態插入 `fonts.googleapis.com` 樣式表 | 可以隨時加任意字型 | 要放寬 CSP（`fonts.googleapis.com`／`fonts.gstatic.com`），訪客瀏覽器會連到 Google（隱私告知）；第三方連線多一次 DNS 與 TLS，首屏較慢 |
  | C. 只用系統字 | 維持現狀，字型堆疊寫好 fallback | 零成本、最快 | Windows（微軟正黑）與 Mac（蘋方）看起來不同；明體、文楷等風格做不出來，範本的設計無法保證 |
  | D. 依頁面文字自建子集字檔 | 發布時只抽出頁面用到的字，產生小型 woff2 | 檔案最小 | 要有字型處理管線；表單錯誤訊息等動態文字會缺字；維護成本高 |

  > 2026-10-29 更新：實作後發現 `next/font/google` 每次 `next build` 都要下載約 450 個分片，CI 的瀏覽器 gate 因此偶發建置失敗。現在改為把同一批分片與 `@font-face` 自架在 `public/fonts/funnel/`（`funnel-fonts.css`），效果與 A 相同，但建置不需要網路。

- **決定**：採用 **A**，並保留 C 當 fallback（字型堆疊不變）。
  - 第一版只登記範本需要的 4 個字族：Noto Sans TC、Noto Serif TC、LXGW WenKai TC、一個拉丁展示字（Space Grotesk）。
  - 每個字族都要以 CSS 變數掛在公開頁根節點，`funnel-typography.ts` 的字型堆疊改成引用這些變數。
  - 只有實際被頁面選用的字族才會被瀏覽器下載（next/font 產生的 `@font-face` 沒被用到就不會載入）。
- **新增字型選項**：

  | value | 字型 | 用途 |
  |---|---|---|
  | `wenkai-tc` | LXGW WenKai TC（霞鶩文楷 TC） | 手作、溫暖風格 |
  | `display-latin` | Space Grotesk（之後若要 Fraunces、DM Serif Display，再登記成獨立選項） | 數字與英文點綴 |

  繁中內文仍以 Noto Sans TC 為主。
- **字重限制**：每頁最多兩個字族、四個字重，避免繁中字型拖慢 LCP（品質規範見 `qa-standards.md` §3.5）。
- **負責**：批次 1 元件 PR。實作前先讀上面那份 next/font 文件與 `01-app/01-getting-started/13-fonts.md`。

### I-3 捲動進場動畫（頁面設定）

- 頁面設定加「捲動進場動畫：關／淡入／上浮」。只對 `section` 第一層子節點生效。
- 使用 IntersectionObserver；`prefers-reduced-motion: reduce` 時完全停用。
- 動畫只能改 opacity／transform，**不得**改變尺寸，否則會造成 CLS 與水平捲動。
- 編輯器內預設停用，避免干擾編輯。
- **負責**：批次 1 元件 PR。

### I-4 行動版固定元素的定位限制

- 頁面內容外框 `FUNNEL_CONTENT_SHELL_STYLE` 設了 `contain: layout paint`，外框內的 `position: fixed` 會相對外框定位並被裁切，無法固定在視窗底部。這是 #499 刻意的安全設計，不可移除。
- 因此「行動版固定報名列」（C-04）必須擇一實作：
  - **方案 A（建議）**：作為頁面層級設定，由平台在外框**外**渲染。內容只能來自結構化欄位（按鈕文字、要捲動到的表單錨點、是否顯示日期），不接受任意 HTML，商家自訂 CSS 也選不到它。
  - **方案 B**：在外框內最後一個子節點用 `position: sticky; bottom: 0`。必須驗證在各瀏覽器都能黏住，且不會蓋住平台揭露文字。
- 不論哪個方案，都不能遮住頁尾的平台揭露與政策連結。固定列出現時，頁面底部要預留等高空間。

### I-5 活動時間統一設定（單一資料來源）

- **現況**：
  1. 漏斗有「線上講座排程與重播」（`funnel-webinar-settings.tsx`），但要手動輸入 **UTC ISO 字串**（例如 `2026-09-17T10:00:00.000Z`），容易填錯。
  2. 綁定的 Live（預錄直播，`Live.scheduledAt`、`replayAvailableUntil`）自己也有一組時間，兩邊各填一次，可能不一致。
  3. 頁面上的 `countdown` 和文字都不讀這組設定：倒數要另外手打截止時間，日期要寫死在文字裡。
- **要求**：
  1. **一個地方設定**：漏斗設定頁的「活動場次」改成日期與時間選擇器，以選定的時區（預設 Asia/Taipei）顯示與輸入，系統轉成 UTC 保存。綁定 Live 時提供「帶入 Live 的開播時間」按鈕，並在兩邊不一致時顯示警告。
     - 是否要合併成同一個欄位，屬資料模型變更，交 engineer-hard 評估。
  2. **頁面嵌入**：
     - C-01 活動資訊列與 C-06 倒數直接讀這組設定。
     - 文字支援動態欄位 `{{webinar.startAt}}`、`{{webinar.date}}`、`{{webinar.time}}`、`{{webinar.title}}`，沿用團隊漏斗已有的 `team-funnel-dynamic-fields.ts`（已定義 `webinar.title`、`webinar.startAt`），擴充到一般一頁式網站。
     - 未設定時間時，顯示「時間公布中」。
  3. **改一次全站更新**：報名頁、感謝頁、加入行事曆、提醒信、LINE 通知都讀同一組時間。
- **之後的擴充（另案，需要 migration）**：週期場次，例如「每週二、四 20:00 的預錄直播」，讓訪客報名時自選場次（S10 systeme.io 的模式），倒數依訪客選的場次計算。這會改動資料模型與報名流程，屬 engineer-hard 範圍，不放在本次 4 批內。
- **負責**：第 1、2 點放在批次 1 元件 PR（日期選擇器與動態欄位），第 3 點的通知整合另開任務。

### 3.1 倒數的使用規則（C-06）

Facebook 廣告常見的一頁式網站多半放倒數。平台**已經有**倒數元件，但目前只有「手動設定截止時間」一種，外觀也只有一種，也不能綁定活動時間。C-06 補齊以下四種模式：

| 模式 | 適用 | 規則 |
|---|---|---|
| `fixed` 固定截止 | 早鳥優惠、限時活動 | 截止時間到了，優惠或報名真的要結束；到期後顯示 `expiredText` |
| `webinar_start` 開播倒數 | 講座報名頁 | 綁 I-5 的開播時間；直播中與回放期自動換文案 |
| `registration_close` 報名截止 | 有截止日的講座 | 綁報名截止時間；截止後表單改為不可送出（平台行為） |
| `visitor` 訪客個別倒數 | 「看完講座後 48 小時內有效」的限時方案（常見於自動化 webinar 與 Facebook 銷售頁） | 起算點與到期時間要**由伺服器保存**，綁在報名紀錄或訪客上。重新整理、換瀏覽器都不得重置。到期後，該方案在結帳端也必須真的失效 |

- **禁止的做法**：
  - 每次重新整理就重新倒數。
  - 每天午夜自動重設的「今日截止」。
  - 截止後優惠照樣有效的假倒數。
- **原因**：
  - 這屬於引人錯誤的廣告表示，有公平交易法第 21 條的風險，也會傷害商家信用。
  - `visitor` 模式若連動優惠價格，還牽涉 checkout，必須由 engineer-hard 實作，並經 reviewer 審查（AGENTS.md）。
  - 第一版的 `visitor` 只做「講座回放期限」這類不牽涉金額的用途。

### 3.2 表單建構器（C-19）

**不建議直接嵌入 JotForm 這類外部表單**。報名表不只是收資料，送出時平台會：

- 建立報名紀錄並綁定 Live
- 寄送提醒信與 LINE 通知
- 記錄推廣歸因與佣金來源
- 套用租戶隔離與個資規範

外部表單的資料不會進入平台，以上功能全部失效。iframe 在手機上的高度、捲動與追蹤也常出問題，資料還會存到第三方。需要問卷或報名以外的用途時，商家仍可用 #499 的自訂程式碼嵌入，但那份表單**不算報名**。

建議做法：把平台表單升級到 JotForm 常用的功能，資料留在平台內。

| 能力 | 內容 | 批次 |
|---|---|---|
| 欄位類型 | 現有：文字、Email、電話、數字。新增：下拉選單、單選、多選（核取方塊群組）、多行文字、日期、縣市＋區域連動選單、LINE ID（格式提示）、同意條款（已有 checkbox） | 批次 2 |
| 欄位屬性 | 必填、提示文字、說明文字、預設值、寬度（整列／半列，手機一律整列）、選項清單（最多 30 項） | 批次 2 |
| 隱藏欄位 | 自動帶入 `utm_source`／`utm_medium`／`utm_campaign`、推廣碼、來源頁；不顯示給訪客，送出時一起保存 | 批次 2 |
| 網址預填 | `?name=` 這類參數預填欄位。只允許非敏感欄位，不預填 Email 以外的個資 | 批次 3 |
| 條件顯示 | 「如果『所在地區』選海外，顯示『WhatsApp』欄位」。條件只支援 等於／包含／已填，最多 10 條 | 批次 3 |
| 多步驟 | 第一步只收姓名＋聯絡方式（先建立報名，避免流失），第二步才問資格題（S1、S4 的兩段式做法） | 批次 3 |
| 驗證 | 台灣手機格式、Email 格式、字數上限；錯誤訊息用繁中、出現在欄位下方，不推擠出水平捲動（`qa-standards.md` L-11） | 批次 2 |
| 送出後 | 導向感謝頁（既有）、顯示訊息、加入行事曆（C-09）、開啟 LINE 加好友（商家設定的網址） | 批次 2 |
| 資料檢視 | 自訂欄位出現在既有的表單提交列表與匯出；提交資料的讀取與匯出一律綁定目前 vendor | 批次 2（engineer-hard 審查資料存取） |
| 防濫用 | 沿用既有 recaptcha 節點與伺服器端速率限制 | 既有 |

- **資料模型**：自訂欄位的答案若需要新的資料表或 JSON 欄位，屬於 migration，要登記到 `docs/codex-goal/PRISMA_INVARIANTS.md`，由 engineer-hard 實作。
- **個資**：新增欄位一律在隱私說明中列出用途；身分證字號、信用卡號這類欄位類型**不提供**。

## 4. 分批計畫：4 批 × 5 個範本，加上第 5 批（21–23）

### 4.1 協作規則（避免多人改同一檔）

- **共用熱點檔案**同一時間只有一個 writer：
  - `funnel-page-document.ts`、`funnel-page-document-renderer.tsx`
  - `funnel-element-inspector.ts(x)`、`funnel-block-library.ts`、`funnel-showcase*.ts(x)`
  - `funnel-template-gallery.ts`、`funnel-template-catalog.ts`
- 所以每一批先由一個工作階段做**元件 PR**，合併後再開 5 個平行的**範本 PR**。
- 每個範本只新增自己的檔案：
  - `src/lib/funnel-templates/webinar/NN-<slug>.ts`
  - `public/funnel-illustrations/webinar/NN/`
  - `src/lib/funnel-templates/webinar/NN-<slug>.test.ts`
- 範本 PR **不要**修改 gallery／catalog 登記。由主對話在該批 5 個範本都合併後，統一做一個「登記 PR」，或由元件 PR 事先放好空位，請主對話擇一。
- 範本 PR 若發現元件 bug，回報給主對話排入下一個元件修正 PR，不要在範本 PR 裡順手修改熱點檔案。
