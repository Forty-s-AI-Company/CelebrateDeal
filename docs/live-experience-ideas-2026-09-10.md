# 直播體驗構想紀錄

日期：2026-09-10

狀態：想法收集與初步評估；使用者已確認「如果是基本的，那就一定要做」。下方基本項目列為產品必做需求，尚未排定實作或變更既定 roadmap；維持先不寫程式。

## 1. 講師與簡報排版

使用者構想（靈感來自 Zoom）：

- PPT 在左、講師攝影機在右。
- 講師攝影機疊在 PPT 上，可選左上、左下、右上、右下。
- 支援講師人像去背。

初步評估：基本排版可行，難度中等，偏向提升專業感的基本配備；去背難度較高，可後續再做。

建議先提供固定比例、攝影機大小與觀眾畫面預覽，避免遮住簡報文字。去背需要考慮頭髮、手部、光線與設備效能。預錄影片若已將人像與 PPT 合成，不能直接自由重排；需要分開素材，或錄製時先決定版型。

## 2. 橫式與直式直播

使用者構想：真正直播與預錄播放都能選擇橫式或直式。

初步評估：可行，完整支援的難度為中高；手機觀眾多時價值較高。直式需要專用版型，不能只裁切橫式畫面。

建議先在建立活動時選擇方向；直播中切換、同時輸出兩種比例尚未列入第一版建議。簡報、圖表與操作示範適合橫式；口播與產品展示可評估直式。手機直拿也可以採橫式影片在上、互動在下，不必強制直式影片。

## 3. 畫面內互動卡片

使用者構想：

- 真直播與預錄皆適用。
- 問題可提前設計，也可現場新增，在講師想發送時出現。
- 觀眾可輸入文字、回答選擇題、回應 666／111／222 等快捷文字，或使用貼圖。
- 橫式觀看時也能直接互動，不必另外打開聊天室。
- 整合到互動留言功能。

初步評估：可行，難度中高，是目前最值得優先驗證的方向。核心價值是降低觀眾回應步驟、幫助講師掌握需求；提升成交仍屬待驗證假設。

建議：

- 使用不大幅遮住內容的互動卡片；實際呈現尚待設計。
- 支援手動發送，以及預錄內容的指定播放時間觸發。
- 分清同步預錄活動與個人自行播放，處理暫停、快轉、重播與重複觸發。
- 真直播需考慮影音延遲，讓問題與觀眾聽到的內容對齊。
- 卡片與聊天室共用回應紀錄，觀眾不需重複輸入；公開與私人回覆需區分。
- 手機原生全螢幕可能限制網頁卡片疊加，後續需驗證播放器行為。

## 4. 隱私聊天室與可控制的彈幕（新增）

### 使用者明確提出的需求

- 聊天室中，觀眾只能與講師互動，看不到其他觀眾的留言，以照顧注重隱私的人。
- 畫面可選擇是否顯示彈幕。
- 觀眾內容中，只有互動卡片的留言或貼圖才會出現在彈幕；一般聊天室留言不進入彈幕。
- 講師可以從直播畫面或後台開關彈幕。
- 觀眾可以從自己的觀看畫面開關彈幕。
- 彈幕也可以使用「互動角色」預先設計的內容，帶動現場氣氛。

### 初步設計建議（尚未定案）

- 講師的畫面開關與後台開關共用同一活動設定；講師關閉時全場停止顯示，講師開啟時觀眾仍可自行隱藏。
- 觀眾開關只影響自己的顯示，不改變其他人的觀看體驗。
- 私人聊天室內容不因講師開啟彈幕而變成公開內容；講師對單一觀眾的回覆亦建議保持私人。
- 互動卡片需清楚告知回答是否會公開展示；僅講師可見的卡片回答不應自動進入彈幕。
- 是否顯示姓名、是否匿名、哪些題型可上彈幕、是否需講師審核，留待設計確認。
- 預先設計的互動角色內容建議標示為角色／預設互動，不冒充真實觀眾的即時留言，也不計入真實觀眾參與統計。
- 角色腳本可考慮手動發送或依預錄時間點觸發；觸發方式、頻率與角色設定尚未定案。
- 彈幕需考慮密度、遮擋 PPT、手機可讀性，避免影響主要內容。

初步價值假設：私人提問降低公開發言壓力，互動卡片與可選彈幕提供公開參與管道，預設角色可協助講師安排暖場節奏。尚未驗證實際需求、付費意願或成效，也未進行現有程式架構可行性審查。

## 初步市場判斷與建議順序

現有產品已提供排版、直式與投票等相近能力，顯示有人服務這些需求，但不等於 CelebrateDeal 的客群已證實願意付費。差異化方向是將觀看、私密提問、公開互動與講師控場整合得更順暢。

前次評估的建議順序：互動卡片 → 基本講師排版 → 直式專用版型 → 去背。新增的隱私聊天室與彈幕應與互動卡片一起釐清可見性規則，實作優先序尚未決定。若客群以手機口播銷售為主，可再提高直式優先度。

不寫程式的驗證方式：找 3～5 位目標講師，以示意畫面配合真實講稿，確認會在哪些時間點發哪些問題、目前如何互動，以及是否需要私人聊天與彈幕。先驗證互動是否更容易，再驗證成交影響。

## 補充決策：基本功能必做

使用者指示：「以上構想都有市場性嗎？如果是基本的，那就一定要做」。以下為依競品能力與 CelebrateDeal 銷講定位所做的產品判斷，不代表已有付費意願或成交提升的量化證據。

| 項目 | 定位與決策 |
| --- | --- |
| PPT 與講師並排、四角子母畫面 | 基本呈現能力，列為必做；不包含已合成預錄影片的自動拆解。 |
| 私人提問、講師回覆、其他觀眾不可見 | 基本隱私能力，列為必做；觀眾彼此不可見是本產品選擇，不是所有直播平台的預設。 |
| 文字問題、選擇題，提前準備或現場建立並手動發送 | 基本互動能力，列為必做。 |
| 手機觀看與互動可用 | 基本觀看品質，列為必做；不等於必須提供原生直式導播。 |
| 畫面內卡片、666 等快捷回應、預錄時間觸發 | 符合產品定位的差異化候選，建議優先；不能全部稱為市場基本配備。 |
| 原生直式直播與專用排版 | 手機導向情境有價值，待客群與內容比例驗證。 |
| 透明人像去背疊在 PPT 上 | 視覺加分，非銷講平台必備；虛擬背景普及不代表透明人像合成必備。 |
| 互動卡片留言／貼圖彈幕 | 氣氛功能，保留評估；做彈幕時，講師總開關、觀眾個人開關與私人內容隔離為必要條件。 |
| 預設互動角色彈幕 | 市場性尚待驗證；保留構想，需能辨識預設內容，不混入真人互動成效。 |
